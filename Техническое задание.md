# 📚 Shelfmate — Техническое задание

> Разработка REST API-сервиса для учёта прочитанных книг, оценок и рецензий — по мотивам Letterboxd, но для книг.

---

## 🛠 Технологический стек

| Категория | Технология |
|---|---|
| 🔧 Контроль версий | Git |
| 🐹 Язык разработки | Golang |
| 🌐 API | REST API |
| 🧭 Роутер | net/http (стандартная библиотека)|
| 🗄 База данных | PostgreSQL |
| 🔄 Миграции | Database Migrations (схема + начальные данные) |
| 🌍 Конфигурация | Переменные окружения |
| 🔐 Аутентификация | Серверные сессии (cookie), пароли хранятся как bcrypt-хеши |
| 📝 Мониторинг | Логгирование, метрики Prometheus, дашборд Grafana |
| ⚙️ Сборка | Makefile |
| 🐳 Контейнеризация | Docker + Docker Compose |

---

## 🧩 Основные сущности

| Сущность | Описание |
|---|---|
| 👤 Пользователь | Читатель, у которого есть своя полка книг |
| 📖 Книга | Запись в общем каталоге, одна на всех пользователей. Каталог заранее заполняется в базе данных |
| 📚 Книга на полке | Книга из каталога, добавленная пользователем к себе в профиль: статус «прочитана», оценка, рецензия |
| 🔑 Сессия | Вход пользователя: случайный токен в cookie; на сервере хранятся его хеш и срок действия |

---

## 📐 Общие правила

#### Идентификаторы

- 🔢 Все `id` — целые числа, генерируются базой данных автоматически
- 🔑 У книги на полке нет собственного `id` — она определяется парой `user_id` + `book_id`

#### Строковые поля

- ✂️ Пробелы в начале и конце строки обрезаются перед валидацией
- 📏 Длина считается в **символах**, а не в байтах (важно для кириллицы)
- 🚫 Строка из одних пробелов считается пустой

#### Пагинация

Все эндпоинты, возвращающие списки, поддерживают параметры:

| Параметр | По умолчанию | Ограничения |
|---|---|---|
| `limit` | `20` | от **1** до **100** |
| `offset` | `0` | от **0** |

Ответ — массив объектов. Если записей нет — пустой массив `[]`.

#### Фильтр по периоду

- 📅 Параметры `from` и `to` в формате `YYYY-MM-DD`, оба опциональны
- 🚫 Если `from > to` → `400 Bad Request`

## ✨ Функциональные требования

### 1. 👤 Управление пользователями

> Регистрация и вход по паролю (логин — никнейм или email). Сессия хранится на сервере, клиенту выдаётся cookie `shelfmate_session` (`HttpOnly`, `SameSite=Lax`). Чтение данных доступно всем, изменение — только владельцу профиля.

#### Доступные операции

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/users/{id}` | Получить одного пользователя |
| `GET` | `/users` | Получить список с опциональной пагинацией |
| `PATCH` | `/users/{id}` | Изменить username / email (только владелец) |
| `DELETE` | `/users/{id}` | Удалить пользователя вместе с его полкой (только владелец) |

> Создание пользователя — это регистрация через `POST /auth/register` (см. «Аутентификация» ниже).

#### Валидация полей

**Username**
- ✅ Обязательное поле (UNIQUE)
- 📏 Минимум: **3 символа**
- 📏 Максимум: **30 символов**
- 🔤 Только латинские буквы, цифры и `_`
- 🚫 Уникальный **без учёта регистра** (`Admin` и `admin` — один и тот же никнейм), при совпадении `409 Conflict`

**Электронная почта (`email`)**
- ✅ Обязательное поле
- 📏 Максимум: **254 символа**
- 📧 Формат `имя@домен.зона`: ровно один `@`, без пробелов, в домене есть точка
- 🔡 Сохраняется в **нижнем регистре**
- 🚫 Уникальное **без учёта регистра**, при совпадении `409 Conflict`
- 🙈 В публичных ответах API не возвращается; владелец видит его через `GET /auth/me`

**Пароль (`password`)**
- ✅ Обязательное поле при регистрации
- 📏 От **8** до **72 символов**; более длинный пароль отклоняется, а не обрезается
- 🔤 Только **латиница, цифры и символы** (печатные ASCII-символы от `!` до `~`); пробелы, кириллица и прочие не-ASCII символы не допускаются, при нарушении `400 Bad Request`
- 🚫 Не должен совпадать с никнеймом
- 🔒 Хранится только в виде bcrypt-хеша, в ответах API и логах не возвращается

**Поле `created_at`**
- ✅ Обязательное поле
- 🔒 Только для чтения — выставляется **автоматически** при создании записи в БД
- 🙈 В ответах API не возвращается, используется для статистики

#### Аутентификация

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/auth/register` | Регистрация: `username`, `email`, `password`. Создаёт пользователя и сразу выдаёт сессию → `201 Created` |
| `POST` | `/auth/login` | Вход: `login` (никнейм или email) и `password` → `200 OK`. Неверный логин или пароль → `401 Unauthorized`, ответ в обоих случаях одинаковый |
| `POST` | `/auth/logout` | Выход: удаляет сессию и очищает cookie. Входа не требует: без сессии тоже `204 No Content` (ошибка сервера при удалении сессии → `500`, cookie очищается в любом случае) |
| `GET` | `/auth/me` | Текущий пользователь (`id`, `username`, `email`). Без входа → `401 Unauthorized` |

- 🔎 Поле `login`: если содержит `@` — поиск по email (без учёта регистра), иначе по никнейму (без учёта регистра)
- 🍪 Сессия — случайный токен в cookie `shelfmate_session` (`HttpOnly`, `SameSite=Lax`, `Path=/`); на сервере хранится только его хеш; срок жизни — **30 дней**
- 🔁 При каждом входе выдаётся новый токен; выход удаляет сессию на сервере
- 👀 Читать данные (пользователей, каталог, полки, ленты, статистику) может любой посетитель
- ✏️ Изменять данные может только владелец: без входа → `401 Unauthorized`, действие над чужим профилем или полкой → `403 Forbidden`
- 🛡 Запросы, изменяющие данные, принимаются только в формате JSON и только с того же сайта (проверяется заголовок `Origin`); `POST` и `PATCH` обязаны иметь `Content-Type: application/json`, в том числе `POST /auth/logout` без тела
- 📦 Размер тела запроса не больше **1 МиБ**: более длинное тело → `400 Bad Request`
- 🖥 Страницы сайта: `/login` (вход по никнейму или email; после входа возврат на `?next=` — только путь на этом же сайте — или в свой профиль) и `/signup` (регистрация: никнейм, email, пароль). В шапке гость видит «Войти» и «Регистрация», вошедший — свой никнейм (ссылка на профиль) и «Выйти»
- 📚 Своя полка на сайте: на странице книги `/books/{id}` вошедший пользователь добавляет книгу («Хочу прочитать» или «Уже прочитал»), отмечает её прочитанной, ставит оценку 1–100 (ползунок и число), пишет, правит и удаляет рецензию, возвращает книгу в «хочу прочитать» или убирает с полки; в своём профиле под обложками есть быстрые кнопки «Прочитано» и «Убрать». Действия, после которых пропадают данные, требуют подтверждения. Гостю вместо кнопок предлагается войти или зарегистрироваться с возвратом на ту же книгу

### 2. 📖 Каталог книг

> Общий каталог книг, единый для всех пользователей. Каталог формируется **заранее** — книги загружаются в таблицу `books` миграцией с начальными данными (seed). Через API каталог доступен **только для чтения**.

#### Доступные операции

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/books/{id}` | Получить одну книгу |
| `GET` | `/books` | Получить список с пагинацией и поиском |
| `GET` | `/books/{id}/reviews` | Получить оценки и рецензии пользователей на книгу с пагинацией |
| `GET` | `/reviews` | Получить свежие рецензии всех пользователей вместе с книгами с пагинацией |

#### Поиск

| Параметр | Описание |
|---|---|
| `title` | Поиск по части названия, без учёта регистра |
| `author` | Поиск по части имени автора, без учёта регистра |

#### Оценки и рецензии

> Показывает, что о книге думают все пользователи. Данные берутся из полок пользователей.

- 📋 В список попадают только записи полок, где есть оценка (`rating`) или рецензия (`review`)
- 👤 Каждый элемент: `user_id`, `username`, `rating`, `review`, `read_at`, `reviewed_at` (у оценки без рецензии `reviewed_at` равен `null`)
- 🔽 Сначала новые — по `read_at` по убыванию
- 🔗 Книги нет в каталоге → `404 Not Found`
- 📭 Книга есть, но отзывов нет → пустой массив `[]`

#### Свежие рецензии

> Лента последних рецензий всех пользователей (используется на главной странице). Данные берутся из полок пользователей.

- 📋 В список попадают только записи полок с рецензией (`review`); оценки без текста не включаются
- 👤 Каждый элемент: объект `review` (`user_id`, `username`, `rating`, `review`, `read_at`, `reviewed_at`) и объект `book` с данными книги из каталога
- 🔽 Сначала новые — по `reviewed_at` по убыванию, при равенстве — по `user_id`, затем по `book_id`
- 📄 Пагинация: параметры `limit` и `offset`
- 📭 Рецензий нет → пустой массив `[]`

#### Поля книги

> Ограничения задаются на уровне таблицы (`NOT NULL`, `CHECK`, `UNIQUE`), чтобы в каталог не попали некорректные данные.

**Название (`title`)**
- ✅ Обязательное поле
- 📏 Минимум: **1 символ**
- 📏 Максимум: **200 символов**

**Автор (`author`)**
- ✅ Обязательное поле
- 📏 Минимум: **1 символ**
- 📏 Максимум: **100 символов**

**Год издания (`year`)**
- ✅ Обязательное поле
- 🔢 Целое число от **1** до **текущего года**

**Количество страниц (`pages`)**
- ✅ Обязательное поле
- 🔢 Целое число от **1** до **32 000**

**Жанр (`genres`)**
- ✅ Обязательное поле
- Жанр может быть один или несколько. Админ сам будет вносить жанры к книгам через миграцию seed books

**Описание (`description`)**
- ✅ Обязательное поле
- 📏 Максимум: **2000 символов**

**Средний рейтинг (`score`)**
- ⬜ Опциональное поле
- 🆕 Изначально `NULL` — у новой книги в каталоге оценок ещё нет
- 🔒 Только для чтения — вычисляется базой данных: триггер на таблице `bookshelf` обновляет сумму и количество оценок книги, `score` = их среднее
- 🔢 Значение от **1** до **100**, округляется до целых чисел
- 🔄 Пересчитывается при каждом изменении оценок книги:
  - пользователь поставил, изменил или убрал оценку
  - пользователь снял отметку «прочитана» (оценка удаляется)
  - пользователь убрал книгу с полки
- 🧹 Если оценок не осталось — снова `NULL`

**Количество прочтений (`reads_count`)**
- 🔒 Только для чтения — количество пользователей, у которых книга на полке отмечена прочитанной. Обновляется тем же триггером

#### Правила

- 🌱 Книги добавляются, изменяются и удаляются только **миграциями**, эндпоинтов для изменения каталога нет
- 🚫 В каталоге не может быть двух книг с одинаковыми **названием и автором** (без учёта регистра) — `UNIQUE (title, author)`
- 🔗 Книга на полке ссылается на книгу из каталога внешним ключом — удалить книгу, которая есть у кого-то на полке, нельзя

### 3. 📚 Полка пользователя

> Пользователь выбирает книги из каталога и добавляет их к себе на полку (в профиль). Для каждой книги на полке он может отметить, прочитана ли она, поставить оценку и написать рецензию. Записи хранятся в таблице `bookshelf`.

#### Доступные операции

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/users/{user_id}/bookshelf` | Добавить книгу из каталога на полку (`book_id` в теле запроса) |
| `GET` | `/users/{user_id}/bookshelf/{book_id}` | Получить книгу с полки: данные книги из каталога + `read`, `added_at`, `read_at`, `rating`, `review`, `reviewed_at`. Если книги нет на полке пользователя → `404` |
| `GET` | `/users/{user_id}/bookshelf` | Получить полку с пагинацией и фильтром `?read=true` / `?read=false` |
| `GET` | `/users/{user_id}/activity` | Лента действий пользователя с полкой: добавил книгу, прочитал книгу. С пагинацией |
| `PATCH` | `/users/{user_id}/bookshelf/{book_id}` | Изменить поле `read` / оценку / рецензию |
| `DELETE` | `/users/{user_id}/bookshelf/{book_id}` | Убрать книгу с полки |

> Чтение полки и ленты активности открыто для всех. Добавлять книги, менять их и убирать с полки может только владелец полки: без входа — `401 Unauthorized`, чужая полка — `403 Forbidden`.

#### Валидация полей

**Поля `user_id`, `book_id`**
- ✅ Обязательные поля
- 🔗 Пользователь и книга должны существовать, иначе `404 Not Found`
- 🔑 Составной первичный ключ `PRIMARY KEY (user_id, book_id)`, отдельного `id` у записи полки нет
- 🔗 `user_id → users(id) ON DELETE CASCADE`, `book_id → books(id)`

**Поле `read`**
- ✅ Обязательное поле (булево значение)
- 🆕 При добавлении на полку по умолчанию `false`

**Оценка (`rating`)**
- ⬜ Опциональное поле
- ⭐ Значение от **1** до **100** с шагом **1**
- 🧹 В `PATCH` можно передать `null`, чтобы убрать оценку

**Рецензия (`review`)**
- ⬜ Опциональное поле
- 📏 Минимум: **1 символ** (если указана)
- 📏 Максимум: **5000 символов** (если указана)
- 🧹 В `PATCH` можно передать `null`, чтобы удалить рецензию

**Поле `added_at`**
- ✅ Обязательное поле (используем TIMESTAMPTZ)
- 🔒 Только для чтения — выставляется **автоматически** при добавлении книги на полку

**Поле `read_at`**
- ⬜ Опциональное поле (используем TIMESTAMPTZ)
- 🔒 Управляется приложением автоматически

**Поле `reviewed_at`**
- ⬜ Опциональное поле (используем TIMESTAMPTZ)
- 🔒 Управляется приложением автоматически: время, когда текст рецензии появился впервые
- ✏️ Правка текста уже опубликованной рецензии дату не меняет

#### Бизнес-правила

```
(user_id, book_id)  →   уникальная пара: книга добавляется на полку
                        только один раз, повторный POST → 409
                        ⇒ у пользователя не больше одной оценки на книгу

read == true        →   read_at IS NOT NULL
                        read_at >= added_at

read == false       →   read_at IS NULL
                        rating IS NULL
                        review IS NULL

review IS NOT NULL  →   reviewed_at IS NOT NULL
                        reviewed_at >= read_at
                        (ставится при первой публикации текста,
                        правка текста дату не меняет)

review IS NULL      →   reviewed_at IS NULL

rating / review     →   можно поставить только прочитанной книге,
                        иначе 409; при снятии отметки read
                        оценка и рецензия удаляются
```

#### Лента активности

> Показывает, что пользователь делал со своей полкой. Собирается из таблицы `bookshelf`, отдельной таблицы событий нет.

- 📋 Одно событие на книгу — по её текущему статусу: `added` (книга на полке, не прочитана, `at = added_at`) или `finished` (книга прочитана, `at = read_at`)
- 👤 Каждый элемент: `name`, `book_id`, `title`, `author`, `rating`, `review`, `at`
- 🔽 Сначала новые — по `at` по убыванию
- 🔗 Пользователя нет → `404 Not Found`
- 📭 Пользователь есть, но полка пустая → пустой массив `[]`
- ⚠️ Если книгу убрали с полки, её события из ленты тоже пропадают

### 4. 📊 Статистика

> Аналитические эндпоинты с гибкой фильтрацией.

#### Источник данных

- 🚫 Отдельной таблицы для статистики **нет**
- 🧮 Системные счётчики считаются SQL-агрегацией (`COUNT ... FILTER`) при каждом запросе
- 🏆 Топы строятся по полям книги `score` и `reads_count`, которые поддерживает триггер базы данных
- 👤 Статистика пользователя и книги рассчитывается сервисом по записям полок при каждом запросе

| Таблица | Раздел | Что из неё берётся |
|---|---|---|
| `users` | 1. Пользователи | Количество пользователей, проверка существования (`404`) |
| `books` | 2. Каталог книг | Количество книг, `title`, `author`, `genres`, `score` для топов и любимых жанра / автора |
| `bookshelf` | 3. Полка пользователя | Всё остальное: книги на полках, прочтения, оценки, рецензии, даты `added_at` / `read_at` / `reviewed_at` |

#### Доступные операции

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/stats` | Статистика по всей системе |
| `GET` | `/stats?user_id={user_id}&from={from}&to={to}` | Персональная статистика пользователя |
| `GET` | `/stats?book_id={book_id}&from={from}&to={to}` | Статистика книги |

#### Параметры

- 🎯 Режим определяется параметром: без параметров — метрики системы, `user_id` — метрики пользователя, `book_id` — метрики книги. От режима зависит набор полей в ответе
- 🚫 Передан и `user_id`, и `book_id` → `400 Bad Request`
- 🔢 `user_id` / `book_id` не целое число → `400 Bad Request`
- 🔗 Пользователь или книга не найдены → `404 Not Found`

#### Фильтры

- 📅 **За временной промежуток** — параметры `from` / `to` (во всех режимах, необязательны). Книги на полке фильтруются по `added_at`, прочитанные — по `read_at`

#### Метрики пользователя

| Метрика | Описание |
|---|---|
| 📚 Книг на полке | Общее количество книг на полке |
| ✅ Прочитано книг | Количество книг с `read == true` |
| 📈 Процент прочитанного | Доля книг, добавленных за период, которые прочитаны в этом же периоде |
| ⏱ Среднее время прочтения | Среднее значение `read_at - added_at` |
| 🏷 Любимый жанр | Самый частый жанр среди прочитанных |
| ✍️ Любимый автор | Самый частый автор среди прочитанных |
| 💬 Рецензий | Количество написанных рецензий |

> При равенстве для любимого жанра / автора выбирается первый по алфавиту. Если данных нет — `null`.

#### Метрики книги

| Метрика | Описание |
|---|---|
| 📚 На полках | Количество пользователей, добавивших книгу на полку |
| ✅ Прочитали | Количество пользователей, прочитавших книгу |
| ⭐ Средняя оценка | Среднее значение `rating` |
| 📊 Распределение оценок | Количество оценок по каждому значению |
| 💬 Рецензий | Количество рецензий |

#### Метрики системы

| Метрика | Описание |
|---|---|
| 👥 Пользователей | Общее количество пользователей |
| 📖 Книг в каталоге | Общее количество книг |
| 📚 Книг на полках | Общее количество книг на полках всех пользователей |
| ✅ Всего прочтений | Количество книг на полках с `read == true` |
| 🏆 Топ по оценке | Книги с наибольшей средней оценкой (`score`) среди книг, у которых не меньше `STATS_MIN_RATINGS` оценок (по умолчанию **30**). При равной оценке — по возрастанию `id` |
| 🔥 Топ по популярности | Книги с наибольшим числом прочтений (`reads_count`). При равном числе — по возрастанию `id` |

> Размер топов задаётся параметром `top` — целое число от **5** до **100**, по умолчанию **5**. Значение вне диапазона или не целое число → `400 Bad Request`.
>
> Топы считаются за всё время: параметры `from` / `to` на них не влияют.

### 5. ⚠️ Обработка ошибок

> Все ошибки возвращаются в едином JSON-формате.

```json
{
    "message": "failed to get book",
    "error": "book with id 999: not found"
}
```

| Код | Когда возвращается |
|---|---|
| `400 Bad Request` | Некорректный JSON, неверные параметры или не пройдена валидация |
| `401 Unauthorized` | Нет входа или сессия недействительна; неверный логин или пароль |
| `403 Forbidden` | Действие над чужим профилем или чужой полкой |
| `404 Not Found` | Пользователь, книга в каталоге или книга на полке не найдены |
| `409 Conflict` | Конфликт с текущим состоянием данных: дубликат или нарушение бизнес-правила |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

### 6. 📈 Мониторинг

> Приложение отдаёт метрики в формате Prometheus. Prometheus раз в 15 секунд их собирает, Grafana рисует дашборд «Shelfmate».

- 🔒 Метрики отдаются на **отдельном порту** `:2112` (переменная `METRICS_ADDR`, путь `/metrics`). Порт не публикуется наружу: к нему ходит только Prometheus по сети Docker. На основном порту `/metrics` отвечает `404`
- 🖥 Prometheus (`127.0.0.1:9090`) и Grafana (`127.0.0.1:3000`) слушают только локальный адрес сервера; на сервере доступ через SSH-туннель. Пароль администратора Grafana задаётся переменной `GRAFANA_ADMIN_PASSWORD`
- ▶️ Запуск и остановка: `make monitoring-up` / `make monitoring-down`

| Метрика | Что показывает |
|---|---|
| `shelfmate_http_requests_total{method,route,status}` | Число запросов. В `route` стоит **шаблон** маршрута (`/api/v1/books/{id}`), а не сам адрес; запросы мимо маршрутов попадают в `unmatched` |
| `shelfmate_http_request_duration_seconds{method,route}` | Время ответа (гистограмма, из неё считаются p50 и p95) |
| `shelfmate_registrations_total` | Успешные регистрации |
| `shelfmate_logins_total{result}` | Попытки входа: `success` и `invalid` (неверный логин или пароль) |
| `shelfmate_shelf_books_added_total` | Книги, добавленные на полку |
| `shelfmate_books_marked_read_total` | Переходы «хочу прочитать» → «прочитано» |
| `shelfmate_reviews_published_total` | Первая непустая рецензия на книгу (правка рецензии не считается) |
| `shelfmate_shelf_books_removed_total` | Книги, убранные с полки |
| `shelfmate_db_pool_{acquired,idle,total}_conns` | Соединения пула PostgreSQL |
| `go_*`, `process_*` | Горутины, память, процессор |

- 🧮 В метках никогда нет `user_id`, `book_id` и любых других значений, которые задаёт пользователь: иначе число временных рядов росло бы без предела
